The bug the parity test caught

The C# job rounds each trade's CHF notional with Math.Round(decimal, 2). For decimals this is banker's rounding: halves go to the even cent. Spark's round() rounds halves up. On prices with three decimals, half cents really occur, and 308 of 2,399 positions came out one cent higher.

The fix is one function, with the reason written next to it:

src/bank_lakehouse/jobs/positions.py
-    return (priced.withColumn("notional_chf", F.round(notional, 2))
+    # C# Math.Round(decimal, 2) is banker's rounding (half to even); Spark's round() is
+    # half up and broke parity on 308 positions. bround() is Spark's half-to-even.
+    return (priced.withColumn("notional_chf", F.bround(notional, 2))

What the job does

Business rules (both versions)

  1. An amended trade counts only in its latest version.
  2. Cancelled trades are dropped.
  3. Notional converted to CHF at the FX rate of the trade date, or the previous available rate. No rate is an error, never a silent zero.
  4. Each trade's CHF notional rounded to the cent, half to even.
  5. Per counterparty and instrument: net quantity, gross CHF notional, number of trades.

How it is verified

  • Unit tests on each business rule (pytest, local Spark).
  • End-to-end parity test: generate trades, run the real C# job and the PySpark port, compare on the business key with exact decimals.
  • CI on every push: lint, then all tests. The run fails if the parity test is skipped, so green always means parity was checked.

Reproduce it

uv sync --extra dev
uv run python -m bank_lakehouse.generate data/raw --trades 20000
dotnet run -c Release --project legacy/PositionAggregator -- data/raw/trades.csv data/raw/fx_rates.csv out/legacy_positions.csv
uv run python -m bank_lakehouse.jobs.positions data/raw/trades.csv data/raw/fx_rates.csv out/migrated_positions.csv
uv run python tools/parity.py out/legacy_positions.csv out/migrated_positions.csv
uv run pytest -q

Needs Python 3.12 with uv, Java 17+ for Spark, and the .NET 8 SDK for the legacy job. The data is synthetic and deterministic.
